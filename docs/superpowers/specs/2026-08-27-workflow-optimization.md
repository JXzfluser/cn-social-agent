# 工作流编辑器优化文档

## 1. 运行管理

### 1.1 运行历史列表
- **功能**：显示所有历史运行记录
- **字段**：运行ID、状态、触发方式、开始时间、结束时间、耗时
- **交互**：点击查看详细结果、筛选（成功/失败/全部）
- **存储**：InsForge `wb_workflow_runs` 表（已有）

### 1.2 执行日志
- **功能**：详细的节点执行日志
- **内容**：每个节点的输入参数、输出结果、错误信息、耗时
- **格式**：JSON 结构化存储
- **查询**：按运行ID、节点ID、时间范围筛选

### 1.3 失败重试
- **功能**：失败节点自动/手动重试
- **配置**：最大重试次数、重试间隔（指数退避）
- **策略**：从失败节点继续、从头重跑
- **UI**：运行结果面板添加「重试」按钮

---

## 2. 节点增强

### 2.1 更多节点类型
| 类别 | 节点 | 说明 |
|------|------|------|
| 动作 | HTTP 请求 | 发送 HTTP 请求 |
| 动作 | 数据库查询 | 查询数据库 |
| 动作 | 文件操作 | 读写文件 |
| 动作 | 代码执行 | 运行 Python/JS 代码 |
| 触发 | 消息触发 | 接收消息时触发 |
| 触发 | Webhook | HTTP 请求触发 |
| 输出 | 发送邮件 | 发送邮件通知 |
| 输出 | 写入文件 | 保存到本地/云存储 |

### 2.2 节点搜索
- **功能**：在左侧面板搜索节点
- **交互**：输入关键词过滤节点列表
- **快捷键**：Ctrl+K 打开搜索

### 2.3 节点分组
- **功能**：将多个节点组合成子工作流
- **交互**：选中多个节点 → 右键「创建组」
- **展开**：双击组展开查看内部节点
- **复用**：组可保存为模板复用

---

## 3. 调试能力

### 3.1 单步执行
- **功能**：逐步执行每个节点
- **交互**：工具栏添加「单步」按钮
- **暂停**：每个节点执行后暂停
- **继续**：点击「继续」执行下一个节点

### 3.2 断点
- **功能**：在特定节点设置断点
- **交互**：右键节点 → 「添加断点」
- **视觉**：断点节点显示红色标记
- **暂停**：执行到断点时自动暂停

### 3.3 数据预览
- **功能**：运行时查看节点输入输出
- **交互**：悬停节点显示数据气泡
- **面板**：点击节点在右侧面板显示实时数据

---

## 4. 数据管理

### 4.1 导入/导出
- **导出**：将工作流导出为 JSON 文件
- **导入**：从 JSON 文件导入工作流
- **格式**：包含节点、边、配置的完整结构
- **UI**：工具栏添加「导入」「导出」按钮

### 4.2 版本历史
- **功能**：记录工作流修改历史
- **存储**：InsForge `wb_workflow_versions` 表
- **交互**：查看历史版本、对比差异、回滚
- **自动**：每次保存自动创建版本

### 4.3 模板市场
- **功能**：分享和导入工作流模板
- **分类**：内容创作、自动化、数据处理
- **搜索**：按名称、标签搜索模板
- **评分**：用户评分和评论

---

## 5. 通知集成

### 5.1 运行通知
- **触发**：运行完成/失败时发送通知
- **渠道**：微信、邮件、Webhook
- **配置**：工作流级别配置通知渠道
- **内容**：运行状态、耗时、错误信息

### 5.2 定时任务管理
- **功能**：查看和管理所有定时触发器
- **列表**：显示所有定时任务、下次执行时间
- **操作**：启用/禁用、修改 Cron、立即执行
- **日志**：定时任务执行历史

---

## 6. UI 优化

### 6.1 连线数据流
- **功能**：连线上显示数据流向动画
- **视觉**：流动的粒子效果
- **颜色**：根据数据类型着色
- **交互**：悬停连线显示数据内容

### 6.2 节点缩略图
- **功能**：节点内容预览
- **显示**：关键配置信息（如 LLM 的 prompt）
- **交互**：悬停展开完整内容

### 6.3 画布小地图
- **功能**：右下角显示缩略图
- **导航**：点击小地图快速定位
- **视口**：显示当前视口范围
- **缩放**：支持缩放小地图

## 技术实现

### 数据库变更
```sql
-- 运行日志表
CREATE TABLE wb_workflow_run_logs (
  id UUID PRIMARY KEY,
  run_id UUID REFERENCES wb_workflow_runs(id),
  node_id TEXT NOT NULL,
  level TEXT DEFAULT 'info',
  message TEXT,
  data JSONB,
  created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 工作流版本表
CREATE TABLE wb_workflow_versions (
  id UUID PRIMARY KEY,
  workflow_id UUID REFERENCES wb_workflows(id),
  version INT NOT NULL,
  nodes JSONB NOT NULL,
  edges JSONB NOT NULL,
  created_at TIMESTAMPTZ DEFAULT NOW()
);
```

### API 新增
- `GET /api/workflows/{id}/runs` - 运行历史（已有）
- `GET /api/workflows/runs/{runId}/logs` - 运行日志
- `POST /api/workflows/runs/{runId}/retry` - 重试运行
- `POST /api/workflows/{id}/export` - 导出工作流
- `POST /api/workflows/import` - 导入工作流
- `GET /api/workflows/{id}/versions` - 版本历史

### 前端新增
- `run-history.js` - 运行历史面板
- `debugger.js` - 调试器（单步、断点）
- `import-export.js` - 导入导出功能
- `minimap.js` - 画布小地图
