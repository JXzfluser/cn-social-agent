---

## 1. 为什么现在做

当前 workbench 已有：Agent 对话、热点开聊、URL 探索、简化参数、L0/L1 渲染。  
缺口是**产品形态仍像「能调工具的聊天」**，不像「能交片的生产线」。

DeerFlow 的档次不来自功能堆叠，而来自：

- 长任务有计划与可见进度  
- 结束必交 **artifact（产物）**  
- Skill 按需、失败可恢复、行为可配置  

我们只借鉴这些纪律，**不**引入沙箱全家桶 / 多子 Agent 并行 / 通用研究框架。

---

## 2. 一句话目标

**把「做成一集可预览、可下载的短视频」做成系统里的一等长任务：有计划、有产物面板、失败能接着干。**

---

## 3. 非目标（本规划明确不做）

- 整盘迁移到 DeerFlow / LangGraph  
- Docker 沙箱、VSCode、通用 bash Agent  
- 多平台发布、SCRM、运营中台（PRD_v2）  
- 再堆一排工坊参数（参数已简化，保持）

---

## 4. 产品形态（目标态）

```
Agent（导演）                    项目交付台（产物）
选题 / 链接 / 热点
    → Plan 条（可见步骤）
    → 提议做片
    → 同一 video project ────────→ 脚本 · L0 草稿 · L1 成片 · 失败原因
                                      预览 / 下载 / 单镜重试
```

### 4.1 做片 Plan（可见进度）

固定 6 步（可跳过已完成）：

| # | 步骤 | 完成条件 |
|---|------|----------|
| 1 | 选题就绪 | 有 topic |
| 2 | 类型已定 | intro / compare / deep_analysis |
| 3 | 要素够用 | 受众或场景至少一项（对话或默认） |
| 4 | 分镜已生成 | project 有 scenes |
| 5 | 草稿可预览 | L0 渲染 done + 可播放 |
| 6 | 成片（可选） | L1 done 且质检通过；否则保持「草稿已交付」 |

Plan 出现在：Chat 卡片顶部 + 短视频工坊项目页。

### 4.2 项目交付物面板（Artifact Panel）

每个 video project 必须一眼看到：

| 产物 | 状态 | 动作 |
|------|------|------|
| 口播脚本 | 有/无 | 查看 |
| 分镜草稿 L0 | 未渲/渲染中/就绪/失败 | 生成 / 预览 / 下载 |
| 成片 L1 | 未升/渲染中/就绪/失败/质检未过 | 升级 / 预览 / 下载 / 重试 |
| 失败原因 | 文案 | 重试草稿 / 重试成片 / 只重试失败镜 |

聊天不再是唯一真相；**项目页 = 交付台**。

### 4.3 Skill 按需（轻量版 DeerFlow Skills）

| 触发 | 加载 |
|------|------|
| 消息含 URL | short-video-researcher |
| 热点/开源 | github-star-growth-video |
| 深度分析/规律/证据 | deep-analysis-video |
| 默认做片 | short-video-director（短） |

未触发时不把全部 Skill 正文塞进 system prompt（控制污染）。

### 4.4 澄清闸门（Clarification）

在调用 `propose_short_video` 前：若缺受众且缺场景 → Agent **不得** propose，只问 1 题。  
实现可先靠 Coach + Skill；Phase 2 再做成硬拦截中间件。

### 4.5 失败恢复（成片信任）

- L1/Agnes：原因可读 +「重试此镜」+「保留草稿」  
- 下载 URL 解析兼容顶层 `url`（已修）  
- 质检不过：不得标「成片」，只能标「草稿（未通过）」

---

## 5. 成功标准

| 指标 | 目标（落地后 2 周内） |
|------|----------------------|
| 新用户能否说清「草稿 vs 成片」 | 抽检 5 人全过 |
| 黄金路径 | 选题→L0 可播 ≤ 3 分钟 P50（本地） |
| Plan 可见 | 做片会话 100% 显示步骤条 |
| 失败可解释 | L1 失败屏有原因 + 下一步 ≥ 95% |
| 参数简单 | 工坊右侧仍只有「类型 + 音色」 |

North Star 仍对齐定位文档：**Ship Rate**（有 L1 预览/下载的项目占比）——本阶段先埋点，不硬追数字。

---

## 6. 分期（产品节奏）

| 阶段 | 周期 | 主题 | 出口 Demo |
|------|------|------|-----------|
| **P0** | 3–5 天 | Plan 条 + 交付物面板 | 打开项目像交片台，不是参数墙 |
| **P1** | 3–5 天 | Skill 按需 + 澄清纪律 + 失败恢复打磨 | URL→草稿一条龙，失败能接着干 |
| **P2** | 1 周 | 埋点漏斗 + 黄金路径 CI | 周会看得见创建→L0→L1→下载 |

---

## 7. 风险与取舍

| 风险 | 缓解 |
|------|------|
| Plan 变成形式主义 | 步骤与真实 project/job 状态绑定，禁止假勾选 |
| 交付面板与 Chat 双真相 | 单一 `project_id`，Chat 只嵌卡片 |
| 又想加回复杂参数 | 高级项继续隐藏；配置进 yaml |
| 抄 DeerFlow 过大 | 本规划禁止沙箱/子 Agent |
